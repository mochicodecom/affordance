The recurring idioms

  • One walk, many filters. Each shape is known in exactly one function; every consumer is a filter over it. Guards: guardEntries. Scope fan-out: selectTargets. Addressing: addressTarget. Running as the system: runAsSystem. A new consumer cannot invent a divergent reading.
  • Lenient / loud pairs. Wherever old data can defeat the engine, there are exactly two resolutions, part of the interface: lenient for a sweep (skip, contribute nothing), loud for an addressed request (throw, naming what failed).
  • Refusals carry codes. Every deliberate no is an AffordanceError with a code from a closed set, declared where it is raised. Adapters translate codes, never error classes. Bugs are not refusals and pass through.
  • Erasure at the authoring boundary. Typed authoring options (StepOptions, ScopedStepOptions) collapse into one machine-facing normal form (StepDefinition) with a single documented cast.
  • Ports for the expensive seam. The lifecycle talks to storage only through LifecyclePort; tests bind an in-memory port, production binds pg. The port is internal — not a public storage abstraction.
  • One environment object. createEngine builds the widest environment once (db, registry lookup, clock, timers, lease timings) and hands it to every subsystem.
  • Loud definition-time validation. step(), anyOf(), caseType(), createEngine() all throw TypeError on malformed definitions — a definition bug fails the deploy, not an evaluation.
  • Curated barrels with literate headers. Each module's index.js is its interface; each file opens with a doc comment stating its contract. The comments are load-bearing documentation.
